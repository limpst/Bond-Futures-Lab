## 1. 국내 실시간 WebSocket — v0.3 §6 미해결 항목 해소

**무엇이 문제였나**: v0.3 은 "같은 계정에서 국내는 REST 만, CME 는 WS 만 열려 있다"고 결론냈다. 국내 WS 는 구독은 성공하는데 tick 이 0건이었기 때문이다.

**진짜 원인**: 시험을 **야간에만** 했다. 국내 파생 실시간 시세는 주간 세션에만 흐르고, 야간(18:00~05:00)에는 구독이 살아 있어도 tick 이 오지 않는다. 채널이 막힌 게 아니라 **시장이 닫혀 있던 것**이다.

| 채널 | 국내 선옵 (주간 09:00~15:45) | 국내 선옵 (야간 18:00~05:00) | CME |
| --- | --- | --- | --- |
| REST 조회 (`t8461`/`o3103`) | ✅ 5분 폴링 | ✅ 5분 폴링 | ❌ 빈 응답 |
| WebSocket (`FC9`/`FH9`/`OVC`) | ✅ **tick 정상** | ❌ tick 0건 | ✅ 수신 |

**따라서 운영 규칙**: 국내는 **주간 = WS(`collect_kr_ws.py`) · 야간 = REST 폴링(`collect_minbars.py`)** 로 채널을 갈라 쓴다. CME 는 종일 WS(`collect_cme_ws.py`).

**부수 이득 — 거래량 정확도**: FC9 는 체결 건별 수량(`cvolume`)을 주므로 봉 거래량을 **합**으로 센다. CME 쪽(OVC)은 세션 누적(`totq`) 차분 방식이라 v0.3 에서 지적한 **"첫 봉 과소계상"** 한계가 남아 있는데, 국내 WS 경로는 이 문제를 구조적으로 피한다.

## 3. 계량 재검정 — 세션을 아느냐 모르느냐로 답이 갈린다

같은 DB, 같은 pair(KTB3−KTB10), 같은 시각. 차이는 **차분·lag 쌍을 세션 안에서만 만드느냐**뿐이다.

| 지표 | naive 전구간 (`econometrics_report.py`) | **세션 인식** (`econ_pair.py`) | 해석 |
| --- | --- | --- | --- |
| 표본 | 1,579 정렬봉 | 1,584봉 · 세션 3개 · 연속쌍 1,550 | 세션 경계 쌍을 버림 |
| AR(1) b | 0.99776 | 0.9971 | — |
| **half-life** | **309.7분 (5.16h)** | **238.4분 (4.0h)** | 30% 차이 |
| ECM γ | −0.00224 | −0.00290 | — |
| t(OLS) | −1.35 | −1.78 | — |
| **t(HAC, lag10)** | **−1.60 → 게이트 미달** | **−1.91 → 게이트(−1.64) 통과** | ⚠️ **판정 역전** |
| ADF (수준) | stat −1.469 · p **0.5486** (전구간) | stat −1.494 · p **0.5365** (최장 세션 711봉) | 둘 다 기각 실패 |
| ADF (1차 차분) | p < 0.001 | p ≈ 1.1e−10 | 차분은 정상 |
| 현재 z (창 120) | −0.96 | −1.24 | 진입 기준 미달, 대기 |

**half-life 추정치의 이력 — 정직하게**

| 시점 | 값 | 무엇이 달랐나 |
| --- | --- | --- |
| 08-24 오전 | 22.8분 | 12시간 이음매 버그 포함 표본 (**착시**) |
| 08-24 저녁 (v0.3) | 527.9분 | 버그 수정 후, 세션 미인식 |
| 08-25 (naive) | 309.7분 | 데이터 하루 추가 |
| **08-25 (세션 인식)** | **238.4분** | 세션 내부 쌍만 사용 |

같은 대상의 반감기가 사흘 사이 22.8 → 527.9 → 309.7 → 238.4분으로 움직였다. **이 숫자로 밴드 폭이나 보유 기간을 정하면 안 된다.** 추정이 흔들리는 이유는 표본(세션 3개)이 짧기 때문이고, 그래서 v0.3 §9 의 1순위(5~10 영업일 축적)는 그대로 1순위다.

**ADF 의 숨은 제약**: 세션 인식 버전의 ADF 는 연속성이 필요해 **가장 긴 세션 711봉(08-23 야간)만** 쓴다. 사흘치를 모아도 ADF 에 들어가는 표본은 여전히 하루치다 — 세션이 길어지지 않으면 ADF 검정력은 늘지 않는다.

## 4. 전략 비교 lab — 비용을 뺀 뒤 같은 자로 재기

`tools/strategy_lab.py`. 백테스트가 아니라 **"지금 가진 표본으로 무엇을 말할 수 있나"** 를 본다.

**함정을 피하려고 넣은 장치 3가지**
1. **세션 경계**: 60분 넘는 공백은 끊고, 포지션은 세션 끝에서 강제 청산(오버나이트 미보유).
2. **look-ahead 차단**: 시그널은 t 봉 **종가**로 만들고 체결은 t+1 봉 **시가**로 한다.
3. **비용**: 왕복 수수료 0.004pt(계약당 편도 1,000원 가정) + Roll(1984) 유효 스프레드의 편도분을 뺀다.

**비용 파라미터 (실측)**: Roll 유효 스프레드 **0.0069pt** → 편도 **0.0035pt** · 왕복 수수료 가정 **0.004pt**.

**읽는 법**
- **IS 열은 차감 항목이 아니라 진단값**이다. 손익은 이미 체결가(t+1 시가) 기준으로 계산되므로 지연 효과는 순손익 안에 들어 있다. IS 는 "결정 시점 대비 얼마나 불리하게 체결됐나"를 따로 보여줄 뿐이다. z 2.0σ 의 +0.020pt(≈2만원)가 7거래에서 지연 때문에 치른 값이다.
- **대조군이 제 역할을 했다.** `mom` 은 `z` 의 부호를 뒤집은 것이라 총손익이 정확히 대칭(+0.39 ↔ −0.39)이고, 비용을 양쪽 다 물어 둘 다 그만큼 깎였다. 평균회귀가 이기고 추세추종이 지는 방향은 **가설과 일치**한다.
- **비용이 얼마나 무거운가**: 1위 전략도 총손익 0.39pt 중 **0.077pt(20%)** 를 비용으로 냈다. 거래가 잦은 1.5σ·볼린저는 0.099pt. 비용을 빼기 전 숫자는 의미가 없다.
- **Sharpe 는 순위용**이다. 100,800봉/년 가정으로 연율화했고 표본은 사흘 — 9.30 같은 절대 수준은 **인용 금지**.

⚠️ **성과로 읽으면 안 되는 이유**: 거래 3~10건, 세션 3개, 그중 하나는 오늘 오후 162봉뿐. 승률 6/7 같은 숫자는 표본이 아니라 우연이다. **이 표의 용도는 "파이프라인이 비용까지 끝에서 끝까지 돈다" + "가설의 방향이 뒤집히지는 않았다" 두 가지뿐**이다.

## 5. 호가 기반 지표 — 첫 계산 (표본 2분)

FH9 로 받은 5단 호가 139행(08-25 14:26:52~14:28:52)에서 계산.

| 지표 | KTB3 (n=52) | KTB10 (n=69) | KTB30 (n=15) |
| --- | --- | --- | --- |
| 호가 스프레드 (ap1−bp1) | 0.0100 pt | 0.0103 pt | 0.0800 pt |
| OBI 평균 | +0.047 | +0.010 | **−0.532** |
| OBI 범위 | −0.30 ~ +0.21 | −0.97 ~ +0.89 | −0.92 ~ +0.50 |
| 1단 잔량 (매수/매도) | 1,821 / 1,616 | 55 / 52 | 6 / 11 |
| 5단 누적 잔량 (매수/매도) | 8,398 / 10,470 | 566 / 387 | 57 / 93 |

**첫 관찰**
- **1단 잔량 격차 33배**(KTB3 1,821 vs KTB10 55). 호가 스프레드는 거의 같은데 깊이가 다르다 — spread 주문은 **얇은 KTB10 다리를 먼저** 체결하는 leg-order 규칙이 옳다는 앞선 보고의 실무 함의를 호가 데이터로 처음 뒷받침했다.
- **KTB10 의 OBI 변동폭이 크다**(−0.97 ~ +0.89). 얇은 호가창이라 몇 계약에 쏠림이 바뀐다 — OBI 를 시그널로 쓰려면 잔량 하한(floor)이 필요하다.
- **KTB30 은 호가 스프레드가 8배(0.08pt)**. 유동성 미달로 당분간 거래 대상이 아니다.

⚠️ **표본 2분.** 이 표는 **파이프라인 검증**이다. 정식 OFI·VOI·MLOFI·Micro-Price 는 주간 세션 전체(약 400분)를 받은 뒤 계산한다.

**데이터 품질 메모**: 139행 중 **3행의 타임스탬프가 `00:00:00`** 으로 찍혔다(FH9 호가시각 필드가 비어 오는 경우). 소수지만 시각 파싱에 fallback 이 필요하다 — 지금은 그냥 들어간다.

## 6. 운영 — 감시와 사고

**수집 감시 (`watch_collect.py`)**: 종목별 거래 시간대를 알고, 그 시간인데 최신 봉이 허용 지연을 넘으면 `stale` 을 화면과 `collect_log` 양쪽에 남긴다. 휴장에는 울리지 않는다. 오늘 15:00 점검 결과 — 8종목 전부 ✓(지연 2~4분).

**하지만 어젯밤 사고를 실시간으로는 못 잡았다**

| 시각(KST) | 판정 | 내용 |
| --- | --- | --- |
| 11:40 | stale | TN/ZB/ZF/ZN/ZT **964분째 지연** · KTB30 18분 지연 |
| 14:14 | stale | CME 5종 88~89분째 지연 |
| 14:42 | stale | CME 4종 17~23분째 지연 |
| 14:59~15:00 | ok | 전부 정상 |

감시 로직은 **정확히 작동했다**(964분 지연을 그대로 집어냈다). 문제는 **사람이 돌릴 때만 돌았다**는 것 — 스케줄러에 편입돼 있지 않아 16시간짜리 결측을 다음 날 아침에야 알았다. 감시기 자체가 **이 사고 때문에 오늘 만들어진 것**이라 사고를 실시간으로 막지는 못했고, 지금도 자동 실행이 아니어서 **다음 밤에 같은 일이 나도 또 못 잡는다.** 그래서 §8 의 1순위가 기능 추가가 아니라 **스케줄 편입**이다.

**수집 로그 통계** (누적 1,196행): ok 1,059 · error 132 · stale 5.

| 오류 | 건수 | 원인 |
| --- | --- | --- |
| `t8461` HTTP 500 `IGW00121` (유효하지 않은 token) | 114 (KTB3/10/30 각 38) | 액세스 토큰 만료 후 재발급 전 호출 |
| `o3103` SSL EOF | 5 | LS 서버 측 연결 끊김 |
| ConnectionAborted (10053) | 2 | 상동 |

토큰 만료 114건이 전체 오류의 86%다. **토큰 만료 감지 후 자동 재발급·재시도**가 다음 수집기 수정의 1순위다.

**인코딩 패치**: 작업 스케줄러 콘솔이 cp949 라 `—` 같은 문자에서 `UnicodeEncodeError` 로 수집기가 죽었다. 5개 도구 전부 stdout/stderr 를 UTF-8 로 재설정하고 못 쓰는 문자는 대체 표기로 흘리도록 했다(`errors="replace"`). **야간 무인 실행에서 죽는 원인 하나를 제거**한 것.
